# whereismykey — API Key 노출 점검 서비스 기획서

> 최초 작성: 2026-09-07
> 상태: 기획 확정 대기 (구현 착수 전)

---

## 1. 목적

우리가 발급했거나 사용 중인 API Key가 **외부에 노출되어 있는지** 자동으로 점검한다.
우리는 해당 키의 **평문을 보관하지 않고**, 다음 정보만 가지고 있다.

| 항목 | 설명 | 예시 |
|------|------|------|
| `prefix` | 키 문자열의 앞부분 (약 7자) | `sk_live` |
| `postfix` | 키 문자열의 **실제 끝부분** (약 7자) | `a1b2c3d` |
| `sha256` | 키 **평문 전체**의 SHA-256 해시 (hex 64자, 솔트 없음) | `9f86d08...` |
| `length` | (선택) 키 전체 길이 — 사용자가 커스텀 | `48` |
| `charset` | (선택) 중간부 문자셋 — 사용자가 커스텀 | `base62` |

점검은 2단계로 나뉜다.

- **1단계 — GitHub**: 공개 저장소에 키가 커밋되어 있는지 (GitHub Code Search API)
- **2단계 — 외부 웹**: 블로그·포럼·문서 등에 키가 게시되어 있는지 (웹 검색 API)

노출이 확인되면 **노출 위치 링크**와 **삭제 권고문**을 리포트로 반환한다.

## 2. 확정된 설계 결정

| # | 항목 | 결정 |
|---|------|------|
| 1 | 해시 대조 | SHA-256, 솔트 없음. 후보 문자열을 그대로 해싱해 대조 |
| 2 | GitHub 범위 | **공개 저장소만**, GitHub Code Search API 사용 (조직 비공개·커밋 히스토리 심층 스캔은 향후) |
| 3 | 웹 검색 | 공급자 인터페이스로 추상화. **기본 구현 = Brave Search API**, Google CSE / SerpAPI 는 교체 가능 |
| 4 | API 동작 | **비동기 잡 + 폴링**: `POST /scans` → `job_id`, `GET /scans/{job_id}` 로 결과 조회 |
| 5 | 토큰 구조 | prefix ≈ 7자, postfix ≈ 7자(실제 끝부분), 하나의 연속된 토큰. length·charset 은 요청에서 커스텀 |
| 6 | 키 종류 | **자체 포맷 + 서드파티 모두 지원** — 탐지 규칙을 플러그인형으로 구성 |
| 7 | 결과 전달 | **v1은 JSON 리포트만**. Slack·이메일 알림은 확장 지점만 설계 |
| 8 | 상태 저장 | **무상태**. 잡 상태는 메모리에만 유지, 재시작 시 소실 허용 |
| 9 | 배포 | **Dockerfile + docker-compose** (단일 컨테이너). k8s/Helm 은 향후 |

## 3. 매칭 로직 (핵심)

해시는 검색어로 쓸 수 없으므로 **"패턴으로 후보 수집 → 후보를 해싱 → 대조"** 방식을 쓴다.

```
1. KeySpec(prefix, postfix, sha256, length?, charset?) 로 정규식 생성
   패턴:  \b{prefix}[{charset}]{a,b}{postfix}\b
   - length 있으면 a = b = length - len(prefix) - len(postfix)
   - length 없으면 a=1, b=256 (안전 상한), charset 기본 = [A-Za-z0-9_-]

2. 소스(GitHub / 웹)에서 받은 텍스트에 정규식 적용 → 후보 토큰 추출

3. 각 후보에 sha256() 계산 후 알려진 sha256 과 비교
   - 일치        → confidence=confirmed,    severity=critical (확정 노출)
   - 패턴만 일치 → confidence=pattern_only, severity=low      (해시 불일치, 경고 수준 낮춤)

4. 발견 시 기록: URL, repo, 파일 경로, 라인 번호, 커밋(가능 시), 주변 스니펫
   ※ 스니펫과 모든 출력에서 키는 반드시 prefix…postfix 형태로 마스킹
```

`pattern_only` 는 기본 포함하되 `severity=low` 로 낮춰 표기한다.
요청 옵션 `include_pattern_only=false` 로 제외 가능.

**판정(verdict)**

| verdict | 조건 |
|---------|------|
| `EXPOSED` | confirmed 발견 1건 이상 |
| `NOT_FOUND` | 후보 없음 / confirmed 없음 |
| `INCONCLUSIVE` | 소스 오류로 일부 단계 미완료 (pattern_only 만 있는 경우 포함) |

## 4. API 설계

### `POST /scans` — 스캔 시작

요청:
```json
{
  "key_spec": {
    "name": "my-service-prod-key",
    "prefix": "sk_live",
    "postfix": "a1b2c3d",
    "sha256": "<hex 64자>",
    "length": 48,
    "charset": "base62",
    "custom_charset": "A-Za-z0-9_-",
    "key_type": "custom"
  },
  "stages": ["github", "web"],
  "options": {
    "max_results_per_source": 50,
    "include_pattern_only": true,
    "fetch_timeout_s": 10
  }
}
```

응답 `202 Accepted`:
```json
{ "job_id": "uuid", "status": "queued", "poll_url": "/scans/uuid" }
```

### 비동기 실행 방식
- `asyncio.create_task` 로 워커 실행, 잡 상태는 `job_store` 의 dict + `asyncio.Lock`.
- 동시 실행 잡 수 제한(`MAX_CONCURRENT_JOBS` 세마포어), 잡 내부 페이지 fetch 동시성 제한(`MAX_CONCURRENT_FETCHES`).
- 무상태 결정에 따라 재시작 시 진행 중 잡은 소실 (문서에 명시). 향후 확장: Redis + RQ/Arq.

## 7. 보안·안전 고려사항

- **키 마스킹 일관성**: 전체 키/후보 문자열을 응답·로그·예외 메시지에 절대 노출하지 않는다. `redaction.py` 를 단일 지점으로 두고 로깅 필터도 적용. 출력은 항상 `prefix…postfix`.
- **요청 본문 로깅 비활성**: `sha256` 자체는 민감정보가 아니지만 요청 본문 로깅은 끈다.
- **SSRF 가드**: 웹 검색 결과의 임의 URL 을 fetch 하므로 `localhost`·사설/링크로컬 IP·비 http(s) 스킴 차단, 리다이렉트 횟수·응답 크기 상한.
- **공급자 ToS 준수**: 공식 API 만 사용. 구글 결과 스크래핑 금지.
- **GitHub Code Search 한계**(리포트에 disclaimer 로 명시): 공개 + 기본 브랜치 + 인덱싱된 리포만, 결과 상한 존재, 2차 레이트리밋. "없음" = "노출 안 됨" 을 보장하지 않는다.

## 8. 테스트 & 린트 계획

- **린트/포맷**: `ruff` (lint + format). `pyproject.toml` 에 설정.
- **테스트**: `pytest` + `pytest-asyncio` + `respx`(httpx 목킹) + `httpx`/`TestClient`.
- 커버리지 대상:
  - `matcher`: 정규식 빌드, 해시 일치/불일치, 엣지케이스(length 미지정, charset custom, prefix·postfix 인접, 유니코드/개행 포함 텍스트)
  - `redaction`: 다양한 입력 마스킹, 로깅 필터
  - `key_spec`: 검증 실패 케이스(잘못된 sha256 길이, 빈 prefix 등)
  - 각 소스: 목킹된 API 응답으로 파싱·정규화
  - `fetcher`: SSRF 가드 차단 케이스
  - `engine`: 가짜 소스 주입해 오케스트레이션·verdict 산출
  - API: `202` 응답, 폴링 상태 전이, 존재하지 않는 job_id `404`, 인증 실패 `401`
- **CI**: GitHub Actions `ci.yml` — `ruff check` + `ruff format --check` + `pytest`.

## 10. 기록해 둔 가정

- prefix/postfix ≈ 7자, 하나의 연속된 토큰이며 postfix 는 키의 실제 끝부분.
- length·charset 미지정 시: 중간부 길이 [1,256], charset `[A-Za-z0-9_-]` 로 가정.
- confirmed 해시 일치 1건이면 `EXPOSED` 로 판정.
- "삭제 권고" = 리포트 텍스트 + 삭제 요청 메시지 템플릿. v1 에서 자동 폐기·자동 메일 발송은 하지 않는다.
